# BOG-ისთვის მოთხოვნის პროექტი: Sandbox და ონლაინ გადახდების ჩართვა

**სტატუსი: პროექტი. არ არის გაგზავნილი.** გაგზავნამდე მფლობელმა უნდა დაამტკიცოს. გაგზავნის არხი: Business Manager → Payments Manager (ან BOG-ის ბიზნეს მომსახურების ელფოსტა). Sandbox-ის მოთხოვნა ასევე შესაძლებელია api.bog.ge-ზე „Request Sandbox Credentials“.

`[…]` ველებს მფლობელი ავსებს. საიდუმლო მონაცემები (client_secret, ანგარიშის ნომერი) ამ წერილში **არ** იწერება.

**თემა:** ონლაინ გადახდების (Payments API) Sandbox წვდომა და ჩართვის ინსტრუქცია — QR Starr (qrapp.ge)

მოგესალმებით,

ვარ ინდივიდუალური მეწარმე გიორგი ხომერიკი (ს/კ: [11-ნიშნა კოდი]), ბრენდი **QR Starr**, ვებგვერდი **https://qrapp.ge**. მაქვს საქართველოს ბანკში ბიზნეს ანგარიში.

**სერვისი:** ციფრული პერსონალური მილოცვა, რომელიც იხსნება ფიზიკურ ბარათზე დაბეჭდილი QR კოდით. ბარათებს ავრცელებენ პარტნიორი მაღაზიები. მომხმარებელი ასკანერებს QR-ს, ქმნის მილოცვას, იხდის **10 ₾**-ს და მილოცვა აქტიურდება მხოლოდ მას შემდეგ, რაც ჩვენი სერვერი გადახდას ბანკთან გადაამოწმებს. პარტნიორის საკომისიოს ვიხდით ჩვენივე შემოსავლიდან (split payment არ გვჭირდება). დღგ-ის გადამხდელად რეგისტრირებული არ ვარ.

**ინტეგრაცია უკვე მზადაა** Payments API-ზე (OAuth2 client credentials, შეკვეთის შექმნა, callback-ის ხელმოწერის შემოწმება SHA256withRSA-ით, receipt-ით გადამოწმება, refund). ტესტირებულია მხოლოდ ლოკალურ სიმულაციაში, ამიტომ გთხოვთ:

1. **Sandbox წვდომა** (client_id / client_secret), sandbox-ის base URL და სატესტო ბარათები; როგორ გავიმეოროთ უარყოფა, 3-D Secure-ის შეცდომა და timeout.
2. **ხელმოწერილი სატესტო callback-ის ნიმუში** და მიმდინარე საჯარო გასაღები. ასევე: callback-ის განმეორების პოლიტიკა, timeout, წყარო IP-ები და გასაღების როტაციის შეტყობინების წესი.
3. გადახდის გვერდის ჰოსტ(ებ)ი `_links.redirect.href`-ში (ჩვენ ვუშვებთ მხოლოდ `payment.bog.ge`-ს) და დაშვებული `redirect_urls` დომენები.
4. **ონლაინ გადახდების ჩართვის მოთხოვნები:** საჭირო დოკუმენტები; ამოწმებთ თუ არა ვებგვერდს და არსებობს თუ არა ჩამონათვალი (გვერდები, მერჩანტის მონაცემები, ბარათების/ბანკის ლოგოები).
5. **პირობები:** საკომისიო (ადგილობრივი/უცხოური ბარათი, Apple Pay, Google Pay), ირიცხება თუ არა ნეტოდ; უცხოური ბარათები; MCC/კატეგორია ჩვენი მოდელისთვის.
6. **დეპოზიტი და ჩარიცხვის ვადა:** ქართულ და ინგლისურ გვერდებზე განსხვავებული ინფორმაციაა (KA: დეპოზიტი არ მოითხოვება, ჩარიცხვა რამდენიმე წუთში; EN: დეპოზიტი ინდივიდუალურად, ჩარიცხვა მომდევნო დღეს). რომელი ეხება ჩვენ?
7. **დაბრუნება (refund):** ვადა, საკომისიო, ბარათზე დაბრუნების დრო, იგზავნება თუ არა callback ყოველთვის.
8. **Chargeback:** შეტყობინების არხი, პასუხის ვადა, მტკიცებულების ფორმატი, საკომისიო.
9. token-ის სიცოცხლის ხანგრძლივობა, API ლიმიტები, `Idempotency-Key`-ის შენახვის პერიოდი.
10. იღებს თუ არა ბარათის მფლობელი ქვითარს ბანკისგან; საჭიროა თუ არა basket-ში დღგ-ის ველები დღგ-ის არაგადამხდელისთვის.
