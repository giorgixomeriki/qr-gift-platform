# Render + Supabase Free — qrapp.ge owner review, checkout disabled

The lowest-cost way to run the real app at `https://qrapp.ge`: one Render
**Starter** web service (about $7/month) and a **Supabase Free** project ($0).
The site sits behind the owner-review gate and checkout is closed, so this is a
review deployment, not a launch. `render.yaml` is the Blueprint.
`docs/OWNER_REVIEW_DEPLOYMENT.md` explains the review mode. `docs/PRODUCTION_DEPLOYMENT.md`
covers the later paid launch.

| | Monthly | Notes |
|---|---|---|
| Render Starter (Frankfurt) | about $7 | always on, 512 MB. `plan: free` costs $0 but sleeps after 15 idle minutes (about 1 min cold start). |
| Supabase Free (eu-central-1) | $0 | 500 MB DB, 1 GB storage, 50 MB per file, pauses after 7 idle days, **no backups** |
| Email | $0 | Supabase's built-in mailer (a few emails an hour) is enough for review |
| qrapp.ge | already paid | Domenebi.ge |

## What the code does for this host

- **Hosted guards on Render.** `isHostedEnvironment` (`src/lib/env-guards.ts`)
  recognises `RENDER=true`, which Render sets for every service, as well as
  `VERCEL=1` or `APP_HOSTED=true`. The service refuses to start if it is
  pointed at a local database or a local Supabase, if it uses the
  `postgres` superuser, if it uses the public dev `app_runtime` password, or if
  `NEXT_PUBLIC_APP_URL` is http.
- **Client IP.** Render may *append* to a client-supplied `X-Forwarded-For`,
  so its first entry can be forged. Outside Vercel, startup requires
  `TRUSTED_PROXY_COUNT` (or `CLIENT_IP_HEADER`). With a count of `n`, the rate
  limiter keys on the `n`-th entry from the right, which the client cannot
  choose. If the count is set too high, the chosen entry is one of Render's
  proxies, which makes limits coarser but never bypassable. See the
  verification steps in §4.
- **50 MB media.** Video is capped at 50 MB, which is Supabase Free's per-file
  maximum. `db:seed` creates or re-aligns the private `greeting-media` bucket
  with the same limit (`MAX_MEDIA_BYTES`).
- **Checkout disabled.** With `PAYMENTS_PROVIDER=TEST` in production, checkout
  is closed. The sender keeps their saved greeting and sees "Payments open
  soon". No order is created and no provider is called. Neither
  `CHECKOUT_ENABLED` nor `ALLOW_TEST_PAYMENTS` can reopen it, and no `BOG_*`
  variable exists on the service.
- **Gate.** `OWNER_REVIEW_GATE_PASSWORD` puts HTTP Basic auth in front of
  everything except `/api/health`.

## 1. Supabase Free project (owner, about 10 minutes)

1. Go to https://supabase.com/dashboard and click **New organization**. Name it
   `QR Starr` and choose the **Free** plan. A separate org lets it move to Pro
   later without touching other projects.
2. Click **New project** in that org. Name it `qr-starr-review` and pick region
   **Central EU (Frankfurt)**. Click **Generate a password**, save it in your
   password manager, then create the project.
3. **Authentication → Sign In / Providers**: turn **off** "Allow new users to
   sign up". Then go to **Authentication → URL Configuration**:
   - Site URL: `https://qrapp.ge`
   - Redirect URLs: add `https://qrapp.ge/**` and `https://qr-starr.onrender.com/**`
4. **Project Settings → API**: copy the Project URL, the anon key and the
   service_role key.
5. Click **Connect** (top bar) and copy the **Session pooler** URI
   (`postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-…pooler.supabase.com:5432/postgres`).
6. On your Mac, run the following from a checkout of this branch that has
   **no `.env.local`**, so no local setting can leak in. Values stay in your
   shell and are never written to the repo:

   ```sh
   ls .env.local 2>/dev/null && echo "STOP: move .env.local away first"
   mkdir -p -m 700 ~/.qrapp-review
   export MIGRATIONS_DATABASE_URL='<session pooler URI with the password filled in>'
   export NEXT_PUBLIC_SUPABASE_URL='https://<ref>.supabase.co'
   export SUPABASE_SERVICE_ROLE_KEY='<service_role key>'
   npm run db:migrate
   npm run db:seed                       # themes, products, 10 GEL price, private 50 MB bucket
   npx tsx scripts/rotate-app-runtime-password.ts \
     --confirm-host=<pooler host from the URI> --out=$HOME/.qrapp-review/database-url
   npx tsx scripts/ops/seed-owner-review.ts --confirm-ref=<ref> --out=$HOME/.qrapp-review/demo-logins.txt
   npm run ops:check-launch-pricing
   unset MIGRATIONS_DATABASE_URL SUPABASE_SERVICE_ROLE_KEY
   ```

   The file `~/.qrapp-review/database-url` now holds `DATABASE_URL` for
   Render, and `demo-logins.txt` holds the demo Super Admin and Partner
   passwords. Both files are mode 0600. Never run `verify:*` or
   `db:dev-bootstrap` against this project.

## 2. Render service (owner, about 10 minutes, about $7/month)

1. Go to https://dashboard.render.com, sign in with GitHub, and give Render
   access to `giorgixomeriki/qr-gift-platform` only.
2. Click **New → Blueprint**, pick the repo and choose branch
   `feat/render-low-cost-hosting`. Render reads `render.yaml`.
3. Fill the four `sync: false` values: `DATABASE_URL` (the file contents from
   §1), `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and
   `SUPABASE_SERVICE_ROLE_KEY`.
4. Review the plan (**Starter**, the only charge) and click **Apply**. The first
   build takes about 5 minutes.
5. Open **qr-starr → Environment** and read `OWNER_REVIEW_GATE_PASSWORD`. That
   is the site password, with user `owner`.
6. Check `https://qr-starr.onrender.com/api/health`, which should return
   `{"status":"ok"}`. Then open `https://qr-starr.onrender.com` and enter the
   gate credentials.

## 3. qrapp.ge (DNS change, owner, after approval)

1. Go to Render → qr-starr → **Settings → Custom Domains → Add** and enter
   `qrapp.ge`. Render adds `www.qrapp.ge` itself and redirects it to the apex.
   Render shows the exact records; the usual ones are:

   | Type | Host | Value |
   |---|---|---|
   | A | `@` | `216.24.57.1` |
   | CNAME | `www` | `qr-starr.onrender.com` |

2. At Domenebi.ge (My domains → qrapp.ge → DNS): the domain currently uses
   **parking** nameservers (`parking1/2.domenebi.ge`, A `217.147.225.186`).
   Switch it to Domenebi's own DNS management first if records can't be
   edited. Then delete the parking `A` record and any `AAAA` records for `@`
   and `www` (Render has no IPv6), and add the two records above.
3. Back in Render, click **Verify**. Render issues the TLS certificate (Let's
   Encrypt) once DNS has propagated, which takes minutes to a few hours.
4. Check with `dig +short qrapp.ge A` (should print `216.24.57.1`) and
   `curl -sI https://www.qrapp.ge` (should print a redirect to
   `https://qrapp.ge/`).

## 4. Confirm the client-IP setting (once, about 2 minutes)

With `CLIENT_IP_DIAGNOSTICS=true`, run:

```sh
curl -s -u owner:<gate password> https://qrapp.ge/api/ops/client-ip
curl -s -u owner:<gate password> -H 'X-Forwarded-For: 6.6.6.6' https://qrapp.ge/api/ops/client-ip
```

- **Pass:** `resolved` is your real public IP (compare with
  `curl -s https://api.ipify.org`) in **both** calls, and the second call does
  not show `6.6.6.6`.
- If `resolved` is a proxy address, look at `headers`. If a single-IP header
  such as `true-client-ip` holds your real IP in both calls, set
  `CLIENT_IP_HEADER=true-client-ip`. Otherwise raise `TRUSTED_PROXY_COUNT`
  until `resolved` is your IP.
- Then set `CLIENT_IP_DIAGNOSTICS=false`. The endpoint returns 404 again.

## 5. Rollback and limits

- **App:** Render → qr-starr → Events → a previous deploy → **Rollback**.
- **Off switch:** Settings → **Suspend** (billing stops). DNS can stay.
- **Supabase Free pauses after 7 idle days.** Click Resume in the dashboard.
  It takes no backups, so it is acceptable only while it holds demo data.
- **Payment reconciliation cron:** `vercel.json`'s cron does not run on Render.
  With checkout closed there is nothing to reconcile. Before payments open, add
  a Render Cron Job (or upgrade the host) and set `CRON_SECRET` and
  `RECONCILE_ADMIN_USER_ID`.
- **Going public later:** remove `OWNER_REVIEW_GATE_PASSWORD`, then follow
  `docs/PRODUCTION_DEPLOYMENT.md` (Supabase Pro with backups, SMTP, legal pages,
  BOG approval).
